# 第27轮前期探索｜同一4B模型的本地闭环与同状态续行

2026-11-26 · 方案。本轮做推理、环境接入和轨迹采样，微调列入后续研究。

## 1. 目的

1. 在同一底座 Qwen3.5-4B 下比较整套按需框架与官方 Agent。观察较小底座下的变化后办理、约束满足及可诊断的错误。
2. 用同一个本地模型续行两条候选决策，观察第26轮的示范和偏好方向是否对模型能力敏感，继续积累可核对的轨迹和稳定样本。

## 2. 复用和接入边界

- 框架组复用第26轮的状态约束与建模、按需认知决策、任务执行与反馈。框架内需要模型的用户回复解析、工作选择、局部语义分析使用同一本地4B。工具事实、算价、授权、写入和调度沿用已有程序。
- 官方组复用官方 LLMAgent 和原生工具循环，共用同一个4B模型、量化版本、生成设定、可见起点、政策、事件时点及预算。先验收原生工具调用和工具结果回传。
- 两组共用同一用户模拟器及其固定后端。可做全本地模式。若原模拟器含模型抽取，用固定后端替换抽取时需要单独联调，并记录其版本、输出和失败；两组在一个批次内使用同一个模拟器配置。模拟器模型调用单列。第26轮结果作为历史参照，4B与旧API的差异按模型和模拟环境变化分别说明。
- 采用同一轮实际执行的评分原则。保留自然语言来源、授权、模型的原始结构化输出、工具、实际数据库写入及用户模拟判定。程序直接推进与模型自主决策分开标记。若用格式约束，独立记录格式通过与业务选择正确。

## 3. 运行顺序

### A. 新设备接入和基线运行

1. 先做离线接口检查和少量不计入正式结果的联调。如能复现用户授权输入、结构化工作输出、原生工具往返、动态事件来源和终点判定，即可冻结新配置。记录设备、运行器版本、模型量化与摘要、上下文长度、采样设定、思考模式。
2. 冻结后，优先复用第26轮登记的换货8题、退货12题。两组各跑一次，共40条主对照。可先按预定顺序跑两类各若干题检查运行状态，正式题与调试题隔离；接口或模拟器需修复时，完整保留该批，另行冻结受影响的复验。
3. 按业务类型分别看合规办结、当前授权、关键首步、工具调用失败和真实写入。对一方失败的题，区分模型选择、语义解析、工具格式、框架执行及模拟器。模型调用、每步延迟与显存作为本地开销观察项。只在同质量配对中比较开销。

### B. 本地同状态续行

复用第26轮的三个检查点，包括换货中的两个偏好状态和一个退货状态。每个状态从相同快照分别执行两个可行首步，续行使用统一的4B策略、用户模拟、事件和评分规则，各重复两次，共12条。

排序按硬约束、正确办结、用户明确偏好、处理投入。保存具体决策对象，区分强制首步和自主决策。出现偏好相同、方向反转、模型或模拟失败时，保留为诊断。只有两条路径可比较且优劣能追溯时，才登记偏好候选。将本地候选与第26轮 API 候选的来源和版本分开。

## 4. 交付和阶段边界

- 本地官方 Agent 与按需框架的配对结果、代表轨迹、模型及模拟器设置。
- SFT 候选和 DPO 续行比较表，含原始当时输入、实际决策、业务依据、最终结果、候选去留和基础题划分。
- 模型能力与接口边界的失败清单。稳定后再扩采及讨论微调；本轮导出和归档为止。
