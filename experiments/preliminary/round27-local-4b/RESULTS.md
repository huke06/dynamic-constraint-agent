# 第27轮 本地4B闭环与同状态续行

本轮完成 **52 条正式轨迹**，包括 40 条主对照和 12 条同状态续行，另完成 12 条定向复验。在冻结的本地配置下，按需框架达到 19/20 个合规终点，官方 LLMAgent 达到 11/20 个。五道官方组原始失败题在修正共享模拟器后达到合规终点，原始差距包含模拟器误判的影响。两道官方组换货题发生了缺少有效当次授权的原生写入。续行产生 3 条 SFT 候选和 2 条 DPO 候选，供事实复核。

[可在 GitHub 核对的证据摘要](EVIDENCE.json)收录冻结标识、正式汇总、逐题判定、续行与复验结果。

## 1. 范围、环境与冻结

| 阶段 | 任务 | 完成轨迹 |
|---|---|---:|

| 正式 B | 3 个检查点、2 个首步、各 2 次 | 12 |

任务复用第26轮的登记清单和受控零售环境。20 个基础题中，稳定参照 4 题、缺证 4 题、预设办理中变化 9 题、初始冲突 3 题。两组逐题核对了同一初始公开历史、任务配置与数据库。原生 LLMAgent 保留官方工具循环，框架组复用按需调度以及第26轮的 `statefix3` 和其模拟器修复链。这个两组设计检验的是整套框架，申报书中的显式状态第三组和模块消融仍属后续验证。[第27轮协议](PROTOCOL.md) · [第26轮任务清单](../round26-api-closeout/configs/TASKS.json)

两组 Agent 和共享模拟器抽取器均使用 `Qwen3.5-4B Q4_K_M`，由 Windows 原生 `llama.cpp b10917` 和 CUDA 13.3 在 RTX 5070 12 GB 上运行。上下文 32,768、单槽、temperature 0、关闭思考模式和上下文移位。共享模拟器用 JSON 抽取结合原话核验，规格或退款方式许可与最终整单批准分别判定。DeepSeek 调用因历史话术和订单字段的外发风险被自动审批拒绝，本轮实际执行走本地接口。每条沿用 40 次 Agent 请求尝试、180,000 已知词元、24 次业务操作、35 轮，单次 Agent 输出上限 1,700 词元。冻结配置与哈希（本地 `results/round27-formal/A_B_04/FREEZE.json`）

正式前通过 177 项离线检查、3 项状态修复回归和 10 条有预期标签的话术回放。32K 原生工具探针核对了订单号、工具调用及工具结果回传。退货范围变化和换货缺货的四条最终联调均触发预设事件并达到合规终点。早期联调与中止的差额诊断保留在各自目录，表中计数采用完成的冻结批次。话术回放（本地 `results/round27-preflight/local06/REPLAY.json`） · 联调终点（本地 `results/round27-preflight/local06/OUTCOMES.json`）

## 2. A 主对照与失败归因

| 业务 | 官方合规终点 | 框架合规终点 | 官方事件后合规 | 框架事件后合规 |
|---|---:|---:|---:|---:|
| 换货 | 2/8 | 8/8 | 1/3 | 3/3 |
| 退货 | 9/12 | 11/12 | 4/6 | 5/6 |
| 合计 | **11/20** | **19/20** | **5/9** | **8/9** |

20 个配对中，双方合规 11 题、仅框架合规 8 题、双方未达合规终点 1 题。合规终点依据实际工具参数、最新有效整单授权、金额和原生数据库终态独立复算。撤回题需要明确应答停止且数据库保持原样。52 条独立复算均与运行器评分一致。正式汇总（本地 `results/round27-formal/A_B_04/SUMMARY.json`） · 逐题配对（本地 `results/round27-formal/A_B_04/PAIRS.json`） · 独立评分（本地 `results/round27-formal/A_B_04/SCORES.json`）

| 题目 | 冻结批次观察 | 归因与复验 |
|---|---|---|
| E_EDB01、E_EDB04 | 官方在缺少当前整单授权时完成原生写入。框架达到合规终点 | 两条官方轨迹均因授权条件未满足判失败。业务数据库是 τ²-bench 模拟库 |
| E_EDB02、E_EDB08 | E_EDB02 的官方回复达到单次输出上限，随后抽取器引用了上一轮的用户话术。E_EDB08 多次达到输出上限，耗尽预算 | E_EDB02 有模型输出截断和模拟器错引两层问题。E_EDB08 保留为预算终止 |
| R_51 | 官方询问合法退款路线，抽取混淆了商品 ID 和支付方式字段 | 绑定实际问句中的退款选项，定向复验两组均合规 |
| R_82、R_89 | 官方已表达撤回后不再办理，模拟器将后附的礼貌收尾处理成新问题 | 定向复验两条官方轨迹均通过。框架 R_89 两批均因无效证据引用反复被拒，数据库无写入，也未达到停止判据 |
| E_EDB05 | 官方列出可用替代规格并请用户选择，抽取输出无法解析 | 复验绑定原话中可核验的请求和可用选项，两组均合规 |
| E_EDB06 | 官方在缺货后反复询问替代规格，模拟器未绑定有效报价 | 第一次复验恢复替代规格许可，又发现抽取器把原话的 `−$8.42` 取成了 `+$8.42`。按原句绑定唯一有符号的整单差额后，两组均达到合规终点。该次官方轨迹仍有一次旧方案尝试，原生工具拒绝，随后新方案取得授权并写入 |

正式换货中，官方共出现 3 次无有效当次授权的原生提交尝试，其中 2 次产生写入。官方换货另有 11 次请求触及输出上限；32K 服务器日志记录的上下文截断为 0，最长 Agent 输入为 25,088 词元。输出上限和上下文窗口是两个实测指标。正式汇总（本地 `results/round27-formal/A_B_04/SUMMARY.json`）

第一批定向复验 8/10 达到合规终点，第二批差额符号复验 2/2。五道受影响的官方组失败题均在对应复验中恢复。原始 40 条成绩采用开跑前冻结的批次，复验各有独立冻结和轨迹。第26轮云端 API 的成绩用作历史参照；两轮的 Agent 模型、模拟器及运行环境均有变化。第一批复验（本地 `results/round27-formal/targeted_recheck01/RECHECK_SUMMARY.json`） · 差额符号复验（本地 `results/round27-formal/targeted_amount02/RECHECK_SUMMARY.json`）

| 指标 | 官方 | 框架 |
|---|---:|---:|
| Agent 请求尝试 | 37 | 22 |
| Agent 输入词元 | 238,553 | 26,451 |
| Agent 输出词元 | 11,182 | 3,689 |

12 条续行有 10 条达到合规终点。6 个同状态配对均通过可见输入一致性核验，两个强制首步均能实际执行。换货的稳定方向反映这些具体状态下的投入差异，候选动作、当时的可见输入与实际轨迹均可回查。续行配对与偏好向量（本地 `results/round27-formal/A_B_04/CONTINUATIONS.json`）

- DPO 共 2 条候选，来自换货 26 的两个偏好状态，随同一基础题留在测试集。两条候选共享各自的当时可见状态；所选首步为预先指定的比较动作。
- 候选已通过本地结构、分组和哈希核验，保留供事实复核。本轮到数据导出为止。
