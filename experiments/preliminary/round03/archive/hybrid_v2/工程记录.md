# 重构过程与保留的失败

任务和用户消息始终沿用第三轮同一案例。没有通过挑选另一任务或重新采样相同请求来取得成功。每次请求完全匹配 kind、消息、工具 schema、采样设置和 token 上限时复用旧响应；输入因程序/上下文修复发生变化时才产生新的响应，日志同时记录来源。

第二项修复没有规定“复核后必须准备方案”，也未屏蔽复核工具，而是补全被压缩掉的执行进度。前后输出存在差异，但这仍是开发迭代，不能据此断言进度记录的独立因果效果。新旧版本的状态与上下文快照完整保存。

程序对“重述”与“变化”的区分依赖结构值比较，不用自然语言关键词猜意图。语义模型说出的候选变化与程序认定的有效变化都留在轨迹中。相同值和大小写等价值不应使确认失效，真正不同的规格仍使相关依据待复核。

工具响应旁的文字不会进入客户对话或被当作用户确认；它以 `non_delivered_tool_preface` 保存。工具调用按一次工作处理，完整原始模型响应仍在日志中。这是消息路由规则，不是删除不利响应。

首次版本的写入评分还将尝试次数与实际成功写入混在一起。后续将实际写对、被拒绝尝试和全过程条件检查分别记录，首次文件不回写；最终版本没有拒绝尝试。

最终确认和写入正确，另发现框架额外说出未经换货条款明确支持的退款时效，已记入语义复核，未重采样消除。说明程序的结构检查并不自动覆盖所有自然语言承诺。

17 项离线检查及精确回放通过。离线回放不调用模型，不增加业务样本。开发所有尝试的真实响应按供应商响应 ID 去重统计在 `audit.json`，旧失败与开发成本不隐藏。申报材料、旧实验与官方文件保持原样。
