# 确认后、提交前只改一件商品规格

第三轮仅用一个 τ²-bench retail 任务（id=0），各组一次，不增加场景或重复次数。基于官方订单 #W2378156 的键盘与恒温器换货，构造共享办理历史，在两项已明确确认、尚未写入时，插入一条用户消息：只把键盘改为 tactile / white / full size，恒温器和支付方式保持原要求。

直接判断组读取完整历史；完整框架组由同一模型从可见历史抽取带来源的事实和判断，状态模块维护版本与依赖失效，再由同一执行模型自由调用官方工具。状态模块没有场景专用字段、预设失效集合或动作序列。两组均可使用历史缓存，自行决定查询、复核、沟通、确认和具体提交参数。

- `方案.md`：对照和评测边界。
- `state.py`：通用证据状态、版本、传递失效和原子更新。
- `run.py`：官方任务/历史构造、离线检查、两组自由办理及日志。
- `audit.py`：不调用模型，重放官方工具与状态更新，核对两组输入、源文件及单列调用成本。
- `review.py`：提取本例的确认前后原始消息和状态证据，供事后语义复核。
- `工程记录.md`：两次工程中断、原始响应精确复用及容错调整的完整记录。
- `selfcheck/<编号>/`：离线检查与场景。
- `results/<编号>/scenario.json`：来源任务、共享历史、用户变更消息、评测端私有目标。
- `model_calls.jsonl`：完整模型请求、原始响应、token 和耗时（区分执行、状态维护、客户回复）。
- `*_trajectory.json`：自由对话、实际工具参数及返回；完整框架同时保存逐轮状态变更。
- `*_result.json`、`results.json`：实际写入评分；确认更新与依据保留另作轨迹复核，不以工具执行成功替代。
- `snapshot/`：脚本、规则、原始任务、完整数据库与模型客户端快照；`metadata.json` 保存其哈希。
