# 第21轮　动态约束复验与框架优化

从第20轮冻结版本分出。第20轮及其结果单独留存。本目录首先复验已发现的问题，再按决策难度扩充题目。

## 已落实的调整

- 多个替代规格同时出现时，受控用户在回复中明确所选规格，并写入同一条用户许可记录。替代许可仍须与整单授权分开核验。
- 核验金额、规格和支付原文时，只容许去掉成对的 Markdown 强调符号。金额与支付事实仍按原业务规则核对。
- 成功转人工后立即结束 Agent 轨迹，并单记转人工。最终登记仍以业务数据库写入为准。
- 框架语义模块只读取当前待解释的用户消息和需要的证据。程序拒绝重复提交已处理引用。决策提示要求沿用当前有效的库存结果，有依据缺失或失效时再查。

## A　复验第20轮问题

- 49（稳定多步）检查静态初始缺货和多选澄清。
- 23、107（动态多商品）检查提交前资源变化，替代确认和更新后的整单授权。
- 29（动态多商品）检查用户改规格、保留另一商品依据，以及语义模块重复处理旧消息。
- 80（稳定基础）作未注入变化的参照，并保留话术与金额核验。
- 每题两组各跑两次，合计20条，独立基础任务数为5。保持同一模型、相同受控条件，交替两组先后顺序，统一记录终点、原始请求、转人工和语义拒绝。
- 逐次核对业务终态、真实授权、首次关键决策和处理过程。只有双方严格质量都过关且没有环境偏差的配对才用于比较开销。第20轮和本轮的组间分数不可直接用于归因，因环境与框架接口均已有修订。

## B　在独立新题上检验框架

建议在 A 复验确认环境可用后，再从未用于调试的零售基础任务选6至8题。保留少量稳定参照，优先扩充以下状态：

1. **先取证还是先推理。** 对同一业务目标设置库存未知和库存已核验两个状态，用户偏好也控制在可比条件下。看是否选对查询、澄清或利用已知条件形成方案。
2. **继续办理还是先补前提。** 在库存信息和用户偏好已经明确时，对比整单方案已授权、仅同意某个替代规格、原授权已失效三类状态。分别记录模型尝试、程序拦截和实际写入。
3. **多个合法选择并存。** 先查备选资源与先澄清用户偏好都可行。选少量这样的共享状态，给两种候选同等的续行条件，另行记录最终结果和中间推进。这可连接申报书的第二个问题。

新题以不同基础任务为单位，重复运行用于看波动。对照先做同框架内的统一入口与按需入口，再做官方 Agent 的端到端比较。固定规则、工具、算价和执行校验后，才用单项对照判断状态或候选机制的作用。首个决策记录工作类型、对象、已有依据和当前缺口。多条路径同样合理时可同时判定通过。
