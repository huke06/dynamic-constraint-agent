# 第 06 轮：同状态续行独立复验

对应当前申报书 3.1.4（1）的局部指令价值比较；状态和执行闭环对应 3.1.1–3.1.3，结果优先及过程成本对应 3.2。不检验完整框架相对基线，不训练，不生成偏好标签。

## 对照与模型职责

一个公开 τ²-bench 零售 Task 0 的受控多轮变体。固定已确认但尚未提交的办理历史，用户修改键盘规格，恒温器及支付要求不变。历史作为给定场景；从分支点后的 8 条续行全部新采样，每重复另采一次公共语义解析。每个重复共享这次解析，两个状态只遮蔽一条可用替代品的 available=true 观察为 null。实际数据库不变；这是显式认识状态干预，不是原生基准返回 null 的声明。

每状态的两分支完整状态、数据库、用户私有规则、随机标记和剩余预算完全一致。已知状态首步比较 screen/clarify：screen 是程序整理缓存中的候选规格、库存与价格，不调用外部库存工具；未知状态比较 inventory/clarify：inventory 调用官方 get_product_details 获得缺失库存，然后派生可用候选。两状态的库存工作并非同一个底层动作，结论是相邻状态下可开展工作价值的比较，不能解释为同一工具动作的纯因果交互。

仅强制首条完整指令 ν=(a,z,K,e)，后续统一使用第 05 轮修订版控制器和执行器。程序维护证据、依赖、四值条件、候选前置条件、金额、权限触发及写入门禁；LLM 处理条件变更语义、后续工作选择、对用户提问与确认措辞、用户回复语义，以及必要时的执行参数。候选菜单和唯一确定参数的程序编译是原实现的限制，不宣称任意业务自主性。

## 校验、冻结与执行

使用现有 `D:/experimentn/tau2-official/.venv/Scripts/python.exe` 运行 `run06.py check`，核对唯一观察差、可行首步、完整快照克隆、旧授权失效、条件许可三种库存取值和禁止越过最终授权。离线测试字句不是在线轨迹。五个业务模块必须与第 05 轮修订成功批次字节一致。

再运行 `python run06.py freeze`，保存全部代码、场景、评分、预算、文档及旧文件/申报书哈希。执行冻结目录内的 `run06.py execute`。禁止重放、替补或失败重跑；不修改冻结文件。执行顺序预定且两重复反转分支顺序，详见 config.json。公共解析若与预注册语义不一致，保留并将该重复记录为初始化失败，不更换样本。线上缺陷照实保留；后续分析文件与冻结结果分开。

模型请求统一 deepseek-flash、temperature=0、thinking=false、retries=0、timeout=60 秒；这是当前别名，不保证跨日期权重相同。记录服务返回 model、system_fingerprint、id。每轨迹 Agent 24 次调用、60000 total tokens、9 项工作；沿用第 05 轮事后扣预算机制，最后一次请求可能越过剩余词元，之后不派发工作。提示输出上限沿用原实现。公共语义解析每重复最多 700 输出词元；模拟用户与评测按原实现每工作/已提交轨迹触发，不占 Agent 预算，另表计费。
