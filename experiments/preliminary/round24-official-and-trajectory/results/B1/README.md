# SFT示例验收

SFT_EXAMPLES.jsonl为12条带审阅元数据的示例，每条messages是实际模型请求原文加实际模型决策；subsequent_effect和pass_reason是事后审阅字段，不能拼进训练输入。SCREENING.json逐条保留52条候选去留，PARTITIONS.json按基础题登记拟议划分。当前没有训练或最终发布数据集。

关键发现：第23轮trace中state的budget/analysis_feedback曾保留可变引用，落盘时可能已是后续状态。因此本轮不把trace.state盲目当输入；以原始model_calls.jsonl中逐次序列化的实际请求为准，通过原始决策匹配对应请求。12条均有真实请求、原始输出、允许执行与严格正确后续。其输入没有环境oracle、未来回复或后续评分。原文件不回改。匹配依据、response_id和源hash都保留。

覆盖信息获取中的用户许可澄清，以及拟案、完整确认、提交。原52候选无query或自主analyze，因此不能凭空提供库存查询/自主分析正例。FORCED_ANALYSIS_REVIEW.json单列强制分析首步，不混入12条自主正例；单步分析虽可执行，也没有同一条完整续行验收，不能据此补齐全链示范。分析类仍是本批的真实覆盖缺口。

拟议按93/29训练、102验证、26/35保留测试登记，所有同题状态/分支/重复一起划分。示例文件可能包含保留测试行供审阅，训练时必须按partition过滤；这些题已经被API实验查看，不能声称是未受人工分析的独立盲测。后续小模型确定后还需新的独立测试题及独立事实复核。
