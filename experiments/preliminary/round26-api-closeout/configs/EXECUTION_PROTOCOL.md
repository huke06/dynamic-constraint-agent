# 联调后执行与评分口径（冻结前）

本文件细化根目录草案，不改变申报书两问和三个模块。第25轮batch01为原准备版16条，先保存源码摘要、通过7项离线回归后运行。16条均正确、未发现自动绕过待解释消息、库存/cap或整单授权。26题的closest理由不作为正确取舍示范。Gate只验收调度安全，不把理由一并宣称全对。

## 题目与数量

主实验20个此前未实际运行的订单：8换货、12退货。按历史case与原始start记录排重，不只按文件名或原题ID。正式清单TASKS.json、事先指定的4题重复REPEATS.json。10个退货来自未调试原题的单订单子任务，另外2退货与8换货为公开DB新订单的受控任务。原题/原订单original.json和改编case.json分别保存，不报原始benchmark分数。新订单不是新行业，当前是同一零售域两类业务。

分层为稳定4、缺证4、实际办理中变化9、初始冲突3。与草案“动态约三分之二”建议不同，本批为补自主查询/分析而保留4个缺证及3个初始冲突；不把初始冲突计成已发生事件。每类均有稳定、缺证、变化和冲突。全部20题×2组，加预定4题×2组复验=48。原第25轮16和同状态12合计76条计划正式，联调另计。

## 业务适配

换货复用冻结v2及第25轮同一按需调度/执行门禁。比较反馈补程序已知的当前库存、整单差额、cap和冲突原因，避免把无精确可行解说成目录/库存不存在；未改旧源码。cap构造先量化到分，两组实际原话和状态值一致。原支付为礼品卡的订单，仅按冻结前确定的结构条件选入：该行所有候选加另一行固定目标都不超过原卡余额，避免把“稳定”题构造成无资金的非法方案。未用任何正式模型结果筛题。

退货单独实现原生return_delivered_order_items与return requested终态，不调用换货接口。退款为原购行价格之和，退款方式仅原方式或现存礼品卡，范围/方式变化使旧整单批准失效。保留已查用户/订单事实，消息语义更新后再拟案/确认。撤回由实际用户消息解释，环境仅在评分侧记录撤回预期；模型必须选择停止/明确应答，不能因没有写入就自动得正确停止。初始退款许可、改变路线许可与完整交易批准独立。

## 公平用户与事件

同模型deepseek-flash、temperature0、thinking disabled；同原生政策、工具、底层DB、初始公开历史、受控用户规则。仅框架有显式状态/候选、程序拟案/模板及前置授权核验。官方保持原生LLMAgent，接入共同传输与日志，不接项目门禁。记录其无授权尝试，即使原生工具拒绝也不能当作无错误。

变化只在实际完整旧方案批准、尚未提交时触发一次。库存更新以真实native assistant-call/tool-result链传给两组；用户要求变化就是同一user原话。模型不见未来事件/私有oracle。模拟仅基于实际话术、已见对象和真实最近用户消息提取；程序再核对实际金额/库存/方式。合法cap/金额依据/退款规则追问得到实质回答。当前active报价和已否定备选分开，最终问题仅指X时不能接受先前已否定Y。多选回复须明确SKU/退款ID并同步环境许可。JSON模板和自然语言方案同规则，不按组名豁免。

退货退款金额按正的原购价格合计核对，可将提取器错误的负号还原为退款幅度；换货仍核对带正负的new-minus-original差额。原始提取保留，不修正Agent给错金额。Markdown标记/空白差异可规范化，字面ID与金额必须真实存在。批准前“暂不执行”不是结束；撤回后需真实停止应答。模拟不覆盖所有自由表达，任何未覆盖合法问题/误许可均单列并排除受影响收益结论。

## 预算、停机与质量

每条40次Agent请求尝试、180000已知词元软限、24业务操作、35轮；每请求输出1700（模拟提取2100）、超时60秒、SDK不重试，仅网络/超时/408/429/5xx一次相同请求重试。程序三次同拒绝停止，失败不替补。未知usage不补0。共用起点构造原生观察不算在线模型调用；其文本进入实际请求时包含在Agent输入，不再重复扣减。公共前缀以消息/观察数量记录，未单独计量词元。停止于首笔登记或明确撤回应答，不采官方写入后的回执；成本仅对应这个业务终点。

主结果=当前真实用户目标、有效当次整单授权、原生参数与数据库终态均正确，撤回题则应答停止且全DB不变。原生参数按item_ids/new_item_ids配对映射比较，列表次序本身不是错误。过程另记首次错误、程序拒绝、话术/理由、无授权尝试、变化后首工作、复用证据、重复工作。明确区分模型错误/程序缺陷/模拟偏差/网络/解析/日志I/O。可比成本须双方主结果正确、事实无矛盾或待核实、无错误尝试和未处理异常、无模拟污染、usage完整。模糊best/closest若无用户指定效用不冒称已证实，保留并单列。

## 同状态与数据

DPO三个起点在DPO_CHECKPOINTS.json，覆盖换货26容量优先/外观优先和全新退货RDB01退款偏好。两个强制首步均先离线实际执行通过，同一完整起点、相同按需续行、同反馈，每支两次共12。强制首步是预注册候选工作，不伪称模型自主生成；候选JSON包含对象、具体SKU/退款方式、依据和完成条件。排序依硬约束→正确办结→实际公开软优先级→投入。只有两次方向稳定且非环境/事实污染才导出DPO；并列、反转、待核实全留。方向针对具体对象与策略，不是工作类型普遍排序；离线核对若直接澄清相同报价，两支在该报价的偏好分应相同。

SFT只收模型实际自主决策：以model_calls序列化请求还原输入/response_id，核对程序未替换动作、实际执行推进、后续质量。自动步骤/强制首步/模型靠纠正办结分开。训练格式只含当时可见messages与决策；后续判定、oracle和评分留在旁置manifest。DPO两响应共享完全相同prompt与当时可见快照，模型不见后续结果。数据划分在PARTITIONS.json按基础任务固定，所有状态/分支/重复随同；24轮保留测试的26/35继续保留测试。独立本地进程验证schema/来源hash/字面引用/同输入/输入边界。导出与验收止步，不进行小模型训练。
