# 动态约束变化后的认知决策小试

本轮检验同一模型在读取相同业务事实、规则、依赖记录和候选工作时，加入程序计算的受影响判断清单，是否有助于它选择更新后的第一项工作。

- `cases.json` 固定场景、候选工作和判定标准。四种情况涵盖用户修改规格、库存数据由未知变为已知、订单进入不可修改的阶段以及与提交无关的字段更新。每种情况同时保留原状态，检验模型是否能继续执行已有依据支持的操作。
- `run.py` 生成配对输入、执行一致的模型调用并评分，也支持离线校验判定逻辑。直接判断组与显式影响组共享完整原始依据。显式影响组只额外看到由依赖关系计算出的待复核记录，不会获得预设答案或下一步建议。
- `results/<运行编号>/` 保留 `metadata.json`、`traces.jsonl`、`summary.md` 和 `snapshot/`。每次运行创建自己的结果目录，并保存当次的场景、运行脚本及模型客户端快照。

## 评测范围

场景为依据本地 τ²-bench 零售政策编写的受控决策快照，使用虚构数据。每个场景提供两个匹配状态，使用同一模型、提示和采样设置对两组各运行两次，计划共 32 次单步模型调用。模型在备选工作中选一项，并给出简短依据。变更后和参照状态分别统计下一步选择符合预设判定的次数、不满足前提的提交选择次数及格式或接口错误。完整轨迹保留，以便逐例审查。

本轮评估第一步决策。后续业务执行、端到端办结率、轨迹学习和模型优化属于后续研究范围。人工编写的少量场景及其重复运行仅用于机制观察。

## 复现

在本目录运行以下命令。在线评测沿用工作区中现有的 DeepSeek 客户端和已配置的凭据。

```powershell
$python = '../../../tau2-official/.venv/Scripts/python.exe'
& $python run.py --check
& $python run.py
```
