# 一个相邻状态的冻结协议

## 唯一干预

沿用第四轮 Task 0 的目标和新用户消息、真实数据库、规则、私有用户偏好、当前用户状态及随机状态。对原公开商品详情中满足 clicky/RGB、非首选 full size、且已知可用的一个替代品，仅将 available=true 改为 null（未知）。完整目录中的规格和价格、full-size RGB clicky 已知不可用、其他变体状态均保持。修复这一处可复原整个初始公开 fixture。

库存未知不是库存变化：底层数据库仍有货。没有把有货改成无货，也不利用私有数据库给程序条件或 Agent 填答案。控制视图、来源工具消息、缓存及从它构造的记录一致未知。该观察删失是受控构造，不冒称原官方工具真实返回 null。

先验已确认的旧无背光商品库存证据仍可保留，它不支持新的 RGB 方案。新方案许可未知，恒温器与支付要求不变。用户仍可在查库存前有条件地接受 80%；程序不能把条件接受当成库存证明或交易授权，也不能为了制造差异强制用户拒绝提前回答。

## 首步与共同续行

旧状态首步 screen 利用已有库存；新增状态首步 inventory 调用未修改的官方 get_product_details，获取实际库存并由程序完成确定筛选。它是 ACQUIRE，不调用用户模拟器。另一首步 clarify 询问客户接受范围。

未知状态初始两个 ready 候选为 inventory 与 clarify；screen 和 prepare 因缺库存依据而不可开展。查询后不强制某个后续序列，由与第四轮相同的 pi_c 继续；若许可在查询前已获知，查询后可直接准备方案，不强制再问。

公共控制提示、工作提示、参数选择提示、用户模拟提示/私有规则、语义处理提示和审计提示全部保持字节一致。新代码在已知状态不新增候选/字段，离线以所有历史请求和结果精确回放验证。没有增加任何框架臂或重采样已知状态。

## 预算与评价

各分支仍为 9 项工作、24 次 Agent 调用、60000 Agent token；同模型名、temperature=0、thinking=false、retries=0。库存查询和程序筛选本身不产生 LLM token；决策、语义及对象层模型调用全部计入 Agent。客户模拟和外部审计单列。共同前缀的原始语义解释输入没有库存信息变化，因此可精确复用，但其原始成本仍单列。

V(s,w;pi_c) 仍分别保存目标办结、必要约束、取得证据/许可/确认的过程和资源。输出两种状态下“库存依据优先 − 先询问”的实际成本差，不能只凭 token 不顾任务或约束结果判优。

两状态对应的是“先建立库存依据”这一状态依赖工作族：已知时整理缓存，未知时真实查询。不是同一个底层动作；差的差只能作单次描述，不能称严格估计的交互效应。每格只有一次，且跨日期的远端模型别名未必对应完全固定权重；记录原始 model/system_fingerprint，不声称稳定首步偏好或保证发生价值反转。

先通过泄漏、未知与否定分离、真实查询、分支隔离、旧状态精确兼容自检再调用模型。任一分支失败照实记录，不换用户规则、库存或预算，不重复采样到成功。申报与旧实验不变。
