# 只增加一个相邻状态后的观察

保留第四轮的 Task 0、用户要求、规则、真实库存、私有偏好和预算。唯一原始观察干预是：公开目录中一个可用 clicky/RGB/80% 替代品的 available=true 变为未知 null；其规格、价格、其他库存及旧确认保留。底层官方数据库未改，之后必须实际查询才能确认该替代品有货。

这是受控的知识状态实验。历史工具返回及其缓存从构造前一致删失该事实，不声称官方工具真实返回过 null，也不把它当作原生 τ²-bench 轨迹。干预可逆检查证明恢复这一个值后整个公开 fixture 与原锚点相同。

## 四格观察

|库存证据状态|首步|工作步数|Agent 调用|Agent token|最终申请与必要检查|
|---|---|---:|---:|---:|---|
|已有证据（旧锚点）|先整理缓存|5|8|30093|通过|
|已有证据（旧锚点）|先问接受范围|4|7|24413|通过|
|需要查询（新增）|先查库存|5|8|29814|通过|

本次“较省 Agent token 的首步”随知识状态改变：已知时先问少 5680；未知时先查少 2999。两状态下实际差值的变化为 -8679 token，仅作描述，不是交互效应的统计估计。

“库存依据优先”在两状态下是不同的具体工作：已有事实时做程序筛选，缺事实时调用官方 get_product_details 并做确定筛选。因此检验的是同一业务内状态依赖的工作选择，而不是强称同一个底层动作的严格处理效应。

## 新增状态实际发生了什么

先查库存：官方查询证实 80% 有货→提出真实可用选项并取得许可→程序准备完整方案→告知新清单、退款和支付并重新确认→一次提交。

先问范围：助手明确说明 80% 库存尚未知，没有把未知说成有货。用户回复“只有确认有货才接受”。这是一条条件许可，不是最终批准。状态保存该规则及原话来源；官方查询后，程序用实际 available=true 激活尺寸许可，无须再问同一个问题。随后准备、确认并提交。

两条路径都是 5 项工作、一次接受范围澄清和一次交易确认，均只查询库存一次。区别不是强制给先问路径增加一轮对话。先问分支多一次条件规则语义提取：1481 Agent token 已计入 32813，其余差额来自条件状态及实际回复/上下文长度等。本结果依赖当前适配实现；若未来合并语义提取，资源差额可能改变，不能将 2999 当成业务本身的必然代价。

先问的首步在返回时尚未使当前许可成立，故原完成测试 permission_known 为 false；但它取得了条件规则这一有效产物，并在查询后建立前提。不能只看首步完成布尔值就把它记为无用。状态前后与条件触发见 `clarify_first_trajectory.json` 和 `semantic_review.json`。

最终两条路径都提交键盘 1151293680→2299424241、恒温器 4983901480→7747408585，原 Mastercard 不变，官方计算差价 -48.31，订单为 exchange requested。旧确认没有覆盖新方案，两条都在新明确确认后提交。

## 方法一致性与成本边界

旧状态没有重采样。新代码对旧状态的 22 条原始模型请求与官方结果全部精确回放一致。公共控制、执行、用户规则和既有语义提示未改；新增的条件许可适配只在旧接口无法表达、且库存未知的真实回复上触发，旧锚点不触发。

新增状态两个分支的完整状态、数据库、用户私有状态、事件与预算起点一致；只替换首步，随后使用同一策略和执行器。两条实际程序/模型请求回放通过；共 12 项离线验收，见 `offline_check.json` 和 `audit.json`。

Agent 包含全部控制、对象层工作和语义调用；客户模拟、外部语义审计单列于 `V_observations.json`。公共前缀语义为沿用的 520 token，单列而不在两个后缀重复计入。续跑共有 24 条逻辑响应，其中 15 条严格匹配旧请求后复用，当前只新增 9 条 API 响应。协议工作量和实际新 API 消耗是不同口径，`audit.json` 分别保存，未把复用当作免费推理。

## 失败、审计与结论限制

首次试跑 `20261121T055608126476Z` 中，先查已办结；先问分支由于把条件许可压成未知，查询后重复询问，又在没有当前方案时误识别为交易批准而停止。该失败及调用完整保留，不能据此宣称先问的业务目标成功率低。

随后补齐条件规则及库存触发依赖，保留用户原话引用；只有实际查询满足条件后才激活尺寸许可，且仍不产生交易授权。修订后复用了整个已成功查询分支和两分支已有的相同问答，不重采样同一输入到成功。故这仍是开发续跑，不是预先冻结的独立测试；失败和新适配开销在审计中单列，不能与最终四格当成独立重复合并。

外部模型语义审计两分支均判通过；引用编号有误，已按真实轨迹另行复核，原模型审计不回写。没有独立人工标注或人类复核。模型名及返回 system_fingerprint 保留；跨日期远端模型的完全固定权重不作保证。

本次观察支持一个具体、可解释的关系：已有库存时可以先澄清；库存未知时先问得到的是带事实前提的许可，必须继续取得库存证据后才能激活。当前实现下，先查的资源开销更小。它不证明任何场景库存未知都应先查，也不证明完整框架优越。没有增加第二个相邻状态，没有扩展任务或训练模型。
