# 第25轮前期探索：将按需调度接回 v2

第24轮共用 v2 的逐步决策设置，稳定第80题中框架选拟案、选确认、理解回复、选提交，各消费一次调用。六组严格可比配对中，框架的 40 次调用可拆为 28 次认知决策和 12 次用户语义解析，官方为 22 次完整 Agent 往返。第21轮已试过由程序推进前提明确的工作；本轮在 v2 保留可核验状态、业务约束和执行契约的基础上，增加按需运行方式。

| 模块 | 程序承担 | 模型调用触发 |
|---|---|---|
| 状态约束与建模 | 结构化工具数据入账，依赖、授权和前提核验，保存信息来源 | 有尚待解释的实际用户回复 |
| 认知决策 | 确定的拟案、确认、提交，以及唯一明确的必要查询；逐次经过 v2 同一执行校验 | 金额或库存冲突、有多个值得比较的后续工作、已有确认需进一步跟进 |
| 任务执行与反馈 | 原生工具、核验与算价、基于程序事实生成澄清文字，记录结果并更新状态 | 模型选出需要解释取舍的分析工作时，沿用 v2 的局部语义分析 |

按需调度和逐步模式共享 v2、同一候选视图、执行器和第24轮 A2 的受控模拟。调度只读取框架已观测状态，不读取模拟用户的内部预期。存在待解释消息、库存冲突、方案变化或授权失效时，重新检查前提。提交仍由 v2 校验当前有效整单授权。程序拒绝后先交给模型，原始工作和反馈都保留。

本轮先比较 v2 逐步和 v2 按需。80稳定、23库存变化、29要求变化、26金额冲突，四道已知任务各两组各两次，共16条计划轨迹。逐题核对当前授权、金额与实际登记，再单列认知、语义和模拟用户调用，并记录程序直接推进次数。当前任务是机制复验。固定框架以后再用独立任务和官方 Agent 做端到端比较。

运行入口：
- 离线测试：`python -B tests/test_on_demand_runtime.py -v`。
- 核对冻结输入并打印试验清单：`python -B experiments/preliminary/round25-on-demand-v2/run25.py --list`。
- 真实 API 对照：`python -B experiments/preliminary/round25-on-demand-v2/run25.py --run batch01`。每个批次创建新目录，另记使用的快照和源码摘要。
