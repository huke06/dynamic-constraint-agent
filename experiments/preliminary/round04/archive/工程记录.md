# 本轮工程与实验记录

本轮只保留同一 Task 0 的一个新关键状态，先做离线验收，再运行两个不同首步的共同续行。没有启动全任务三组实验，没有训练模型。

## 离线阶段

最初验收发现评分函数少导入 Decimal，在线调用之前修正。随后补充了空参数工作指令的执行路由测试、唯一匹配无模型调用、多匹配由语义执行器处理等测试。最终 15 项通过。离线断言是实现检查，不计作 Agent 成绩，也不是独立影响标注。

## 首次在线协议：040255369430Z

两个首步和共同续行均获得了 80% 许可，但在准备方案处因空参数发生 KeyError。控制器已经选择正确工作，却未填写具体方案参数。原接口要求控制层完成对象层方案分析，与申报的决策/执行分工冲突。两分支均保存为未完成，未计成功。

修正：控制器发 u=(a,z,K,e)；执行器按工作处理。准备工作先由程序筛选，唯一匹配用程序形成参数，多项真正歧义交 LLM 选择。提交只使用当前明确确认的方案。模型仍选择工作，程序没有读取最终目标答案或写死新规格 ID。相关指令、参数来源与完成测试均留痕。

首次运行期间保护范围里出现一个新建的申报分页文档，它不在开始清单中，已记录为新增路径；不是旧文件内容被修改。该运行的保护断言将新增误算为全部不一致。后续将“已跟踪文件改动”和“并行出现的新文件”分开报告，不触碰外部文档。实验目录之外没有写入操作。

## 修正后冻结协议：041352631194Z

更正协议和代码先快照，再复制共同状态进行两分支。策略提示的控制/执行边界已修正，不能把首次未完成轨迹与本次结果合并作重复试验。

对完全一致的请求、模型提示、采样和 token 上限复用原响应，保存 reused_from 与 occurrence；变化的请求只调用一次。最终协议 22 条逻辑模型响应，7 条复用，15 条新增；其中 Agent 16 条（含公共前缀 1 条）、用户环境 4 条、外部审计 2 条。重放不调用模型。

按供应商响应 ID 去重复用，全部开发实际产生 Agent 20 条、74608 token；用户环境 4 条、4825 token；外部审计 2 条、14945 token。这些开发开销单列，不混入首步后缀的效果比较，也不隐藏失败开销。

两分支最终正确提交，外部语义审计判通过，但审计模型有消息索引误引；本助手按真实轨迹修正引用并记录过程冗余，没有再调用模型重评到满意。没有独立人工复核，结论范围按此限制。
