# 同状态候选续行的实际观察

本轮对应申报书 3.1.4 的局部实验，不再用两个不同系统的完整后缀冒充同状态首步比较。基础仍是 τ²-bench retail Task 0，完整官方库存与原办理历史保留；新用户消息撤回无背光许可，要求 clicky、RGB，全尺寸优先，尚未许可尺寸替代。身份、恒温器和支付要求不变。

## 数学对象与运行记录

- s=(g,F,C,P,H,D)：保存在 `decision_snapshot.json`。条件四值与依据有效性分开；旧匹配复核后再传播变化。
- W、Pre、W_ready：初始候选保存在 `W_at_fork.json`；初始 ready 为整理替代 screen 和澄清许可 clarify，其余因各自前提受阻。
- u=(a,z,K,e)：每步轨迹保存工作类别、对象、依据和完成测试；控制层决定工作，执行器不重新选择工作类别。
- V(s,w;pi_c)：保存在 `V_observations.json`，包括成功/约束观察、过程和 Agent/环境/评测分项投入。每分支 n=1，仅为观察，不是稳定概率估计。

`screen_first_start.json` 与 `clarify_first_start.json` 包含的状态、完整数据库、用户私有目标与状态、事件进度、随机状态、预算逐项一致，并与公共快照哈希一致。两个分支只强制执行不同首步；所有后续工作由同一个冻结 pi_c 在各自新状态下选择。程序和所有实际模型请求可无 API 重放，结果一致。

两者均获得用户明确接受 80% RGB clicky 键盘的许可，再告知两项完整清单和退款，并重新获得授权。实际调用官方工具一次，键盘 1151293680→2299424241，恒温器 4983901480→7747408585，支付方式 credit_card_9513926，合计差价 -48.31，订单成为 exchange requested。这是正确提交换货申请，不等于实物换货已完成。

先澄清的工作执行器直接利用已有完整库存提出具体 80% 选项，没有被故意限制证据。用户由此给出许可，后续程序在准备方案时完成确定筛选和计算，因此没有必要再单独做 screen。这个负例应保留：不是每个看起来合理的复核/整理都必须单列为一步。

本次差额为 5680 Agent token、一项工作和一次控制调用。它是在此快照、此策略及实际回复下的单次差额，不足以估计期望收益或断言应总是先澄清。不同首步还引起了后续表述长度等变化，成本应按完整共同续行观察，不只比较两个首步的直接耗费。

## 成本没有混入客户模拟

公共前缀语义解释：Agent 1 次、520 token，单列而不在两后缀重复收费。

|实验角色|先整理|先澄清|计入 Agent 指标？|
|---|---:|---:|---|
|Agent 控制、工作和语义处理|30093|24413|是|
|客户模拟|2449|2376|否，环境开销|
|外部语义审计|7531|7414|否，评测开销|

Agent 读取用户回复的输入 token 已正常包含在 Agent 输入。程序筛选、计算、参数形成与官方写入没有隐藏 LLM 调用。若每项只有一个符合已获许可要求的匹配，由程序形成参数；真正多匹配歧义才由执行 LLM 处理，离线测试覆盖该路由。

两个分支都为一次澄清、一次最终确认。程序保留恒温器原确认及支付等记录的值、版本和来源。但先整理分支的问题里又请求确认未变恒温器/支付，存在不必要的语言重述；程序保留依据不等于模型所有沟通都无重复。该过程问题在人工式轨迹复核中单列，不隐去。

## 验证与剩余边界

15 项离线验收通过；完整起点、分支隔离、实际请求/程序/官方写入的重放通过。253 个已跟踪旧实验、审计、申报与官方文件哈希核对通过。审计文件为 `audit.json`。

外部语义模型对两分支的目标、更新确认及未支持承诺均判通过；本助手又依据实际消息索引核对，见 `semantic_review.json`。语义审计模型给先整理分支引用的部分消息编号不准确，因此没有把它的编号直接当证据；原始审计保留，实际索引另存。这不是独立人工复核，也不是独立人工影响集标注。

本例不需要人为设置 REASON：当前确定筛选与金额都适合程序。仍未开展复杂偏好推理、多任务、相邻状态、重复试验，以及自由 Agent/一般状态/关联状态的完整三组对照。本轮只说明局部续行实验链条已运行并可核对，不能宣称全部申报方法或框架优势已验证。

首次两分支因控制/执行参数接口职责错误而未办结，保存在 `20261120T040255369430Z`，没有删除或计为成功。修正后只复用请求、提示和设置完全相同的 7 条旧响应，其余请求重新产生；这不是独立测试，也没有重采样相同请求直到成功。全部开发真实响应按 ID 去重的 Agent、用户环境及评测消耗另见 `audit.json`，失败开销未并入本次后缀比较，也未隐藏。
