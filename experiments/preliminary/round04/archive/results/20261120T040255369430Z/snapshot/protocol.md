# 冻结协议：一个状态，两项首步，共同续行

## 本轮检验范围

以当前申报书 3.1.1—3.1.4 为依据，实现并检查同状态候选续行。不是自由 Agent/一般状态/完整框架的三组完整任务评测，不据此声称框架性能优越。

状态为 s=(g,F,C,P,H,D)。程序从旧共同历史入账官方工具结果；旧确认方案来自已保存的语义记录并按官方商品和金额检查。新增用户消息由 LLM 解释为必要选项、优先选项及未知替代许可。工具事实不由 LLM 重写。

新要求先更新 g，直接依赖记待复核，再通过程序重查旧匹配；结论发生变化后向差价、确认、合计和整单授权传播。条件四值（满足、未满足、未知、不适用）与依据是否需复核独立保存。旧确认作为历史保留，不能授权新条款。未变恒温器及支付相关记录保持值、版本和来源。

## W、前提与执行指令

候选按当前缺口由能力模板实例化，记录 work_type、target、evidence_refs、preconditions、expected_output、expected_effects、completion_test。W_ready 对各候选自己的适用条件检查，不以提交尚未授权阻塞查询或澄清。

关键状态有两项 ready 候选：

- `screen`：程序基于原缓存列出满足新必要条件的可用替代及偏好可用性，不能推定用户许可。
- `clarify`：获取用户对尺寸/范围的选择，允许利用已有真实库存事实；不故意限制证据以制造差异。

两项可能等价，一项也可能没有额外收益。实际先问的问题由同一语义工作执行器形成，不使用预写“正确问题”。精确筛选/金额由程序完成，不人为设置 REASON 分支。

控制器对 ready 候选说明后续作用与剩余缺口，输出 u=(a,z,K,e)；程序校验对象、引用、类别、前提与完成测试，执行器不再选择工作类别。准备与提交参数由控制模型从观察结果选择，程序只校验和计算，不读取最终目标答案。

## 分支与共同策略

快照包括六部分状态、完整数据库、公开历史、用户私有目标及当前模拟状态、事件进度、随机状态和剩余预算。对首步 screen 和 clarify 各克隆一次。仅首步被实验干预指定；后续完全相同 pi_c、执行器、政策、工具、模型和采样设置。

私有用户规则固定：若全尺寸 clicky/RGB 无货，可接受明确提出的 clicky/RGB/80%，不接受 60%、无背光或白色背光替代；未提出具体方案的泛泛询问可要求说明选项。优先保留可接受键盘，不能通过误导用户随意删掉它。只在得知没有可接受选项时才考虑仅换恒温器。较小尺寸许可不等于具体清单和差价的交易授权。

私有规则只供用户模拟和事后语义评测，不进入 Agent 的状态、决策或对象层输入。两分支的回复文字可以因问题不同而不同，但规则与起始用户状态不变。temperature=0 不保证供应商后端完全确定；本轮记录全部实际响应，不将快照克隆宣称为能控制远端随机性。

## 预算、错误与成本

固定 deepseek-flash，temperature=0，thinking=false，retries=0，timeout=60。每个后缀最多 9 项工作、24 次 Agent 调用、60000 Agent token；达到限制则失败停止，不增加预算或重采样。

Agent 包括 controller、worker、user_semantics。确定性筛选、计算和官方提交没有额外模型调用。environment_user 与 external_evaluation 单列，不能加入 Agent 成本。Agent 读取客户文本仍计入其输入。初始语义解释作为公共前缀成本单列，不在后缀重复计入。

每项工作记录本地进程 CPU（含客户端处理）与完整墙钟时间（含模型/客户 I/O），不将后者冒称程序算法耗时。语义和接口错误保留，不靠拦截后换正确参数代替 Agent。某分支失败后仍运行另一分支，前者不丢弃。

## V 和结论

V(s,w;pi_c)=(p_success,p_constraint,q_process,c_resource)。本次 n=1，只保存观察值，不估计稳定概率、显著性或加权综合分数。q 记录权限/确认是否补足、实际工作、保留依据和阻塞变化；c 按上述角色计费。

程序核对官方申请写入、同款可用、目标选项、实际确认及金额。另用不参与控制的语义审计调用检查用户目标、确认与未获依据的承诺；它不替代独立人工复核，审计错误则该维度未知。任务成功与全部约束满足分别保存，不能只凭工具接受认定全合规。

独立人工影响标注、重复运行、相邻状态对照和完整框架三组对照均尚未开展。本轮目的仅为让申报的数学对象、数据结构和局部续行实验真正对应并可检查。
