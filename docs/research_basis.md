# 研究定位与证据边界

依据当前《2027创新类计划项目申报书_分页紧凑版.docx》2.1与研究计划日志，保留两个问题：

1. Agent如何依据动态业务状态合理开展认知决策？
2. 如何利用执行反馈评价并提升Agent的认知决策能力？

第一条路线按三个模块接成闭环：**状态约束与建模 → 认知决策 → 任务执行与反馈 → 更新状态**。第二条路线从同状态可执行候选及共同续行中取得可核验比较，研究评价与后续学习信号。第23轮用当前API模型验收框架及试采流程，不以训练结果或预定收益作为结论。

`state_model.py`维护原购、初始请求历史、当前有效许可、硬约束与当前批准，计算事实判定与来源；`decision.py`由模型选工作/对象/依据/完成条件；`execution.py`执行查询、分析、澄清、拟案、确认、提交，返回实际结果或拒绝，再进入状态。公共原生工具与来源跟踪实现保存在compat，并标明历史来源。程序处理可判定事实和契约，模型处理当前工作的选择、规格取舍和真实用户语义。

官方LLMAgent端到端受控变体对照沿用第21轮定位，另行独立批次；本轮不混入官方组，也不把项目执行辅助伪装成官方基线。v1新题11/16、v2独立新题26/35原业务均是退货，本轮换货为明确归档的受控改编，不报告原始benchmark分数。状态、重复与同一基础题不能当作独立题增加样本量。候选与评分答案不混入同一模型输入。

本仓库尚无数据支持训练提升或普遍路径排序。示范/偏好候选须同时通过工作可执行、事实/许可/授权来源、办理结果、无环境污染和重复稳定性核对；样本按基础任务一起划分，后续结果不能进入决策输入。相当、排序反转和失败均保留。
